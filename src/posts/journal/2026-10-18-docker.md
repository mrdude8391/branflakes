### Why docker? It's purpose

You develop and write code locally. When you want to run the code somewhere else, you use Docker. For example your fast-api backend server. When you move to a new computer, you need to first install and set up `python`, create the `venv`, install all the packages from `requirements.txt`, and then start the `venv`, and then start the server either with `uvicorn src.main:app --reload`. When the backend is uploaded to a cloud machine on AWS how do you tell the machine to do all these things? Docker.

### Dockerfile

`Dockerfile` no extension defines the docker image. This file is what lets you create and specify how the image looks.
Useful to also include a `.dockerignore`.

> for the fast-api container we don't need to use the `venv` since the Docker image IS the environment.

```yaml
# Dockerfile
# Start From the official Python image
FROM python:3.14-slim
# Set the working directory in the container
WORKDIR /server-py
# Copy the dependencies file to the working directory
COPY requirements.txt .
# Install any dependencies
RUN pip install --no-cache-dir -r requirements.txt
# Copy the content of the local src directory to the working directory
COPY . .
# Expose the port the app runs on
EXPOSE 8000
# Command to run the application. --host at 0.0.0.0 allows the app to be accessible from outside the container.
CMD ["uvicorn", "src.main:app", "--host", "0.0.0.0", "--reload", "--port", "8000"]
```

#### Build or Update Image

`-t` flag names the image. `.` tells Docker to look in the current directory.

```bash
docker build -t <image-name> <location>
docker build -t my-fastapi-app .
```

#### Run Container

`--rm` Automatically removes the container when it exits. `-p` Publishes (forwards) a port. Maps `8000` on my computer to `8000` in the container. `--env-file .env` Injects environment variables.

```bash
docker run --rm -p 8000:8000 --env-file .env sports-api
docker run sports-api
```

### Docker-Compose.yml file

To run a Docker Compose file. Such as the `docker-compose.test.yml` file for my pytests. `cd` to the folder of the file. `-f` to specify the exact file name and location (ie. if it's named anything other than `docker-compose.yml`). `-d` to run the detached, when you run a container in detached mode, it means the containers run in the background of your terminal. Without it, you will see a live stream of all log outputs from the containers.

```bash
docker compose up
docker compose -f .\docker-compose.test.yml up -d
```
